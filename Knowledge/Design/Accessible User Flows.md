# Accessible user flows

## UX research

Start with the user's goal, context, and recovery needs. Treat a proposed flow as a hypothesis until observations support it. Record participants and findings only after actual research and appropriate consent.

## UI review

For each step describe the default, empty, loading, failed, and completed states. Check labels, keyboard access, focus visibility, error identification, reflow, and alternatives to color-only meaning. [WCAG 2.2](https://www.w3.org/TR/WCAG22/) defines testable accessibility criteria; this short note is a review prompt, not a conformance audit.

Use the synthetic [[Projects/Example Issue Tracker/UI Accessibility|project checklist]] to plan evidence, and put execution results in [[Projects/Example Issue Tracker/Test Plan]].
